====== Option +spreadsheet_text_policy+

Specifies how the writer treats \String fields whose text a spreadsheet
application may interpret as a formula instead of as literal text.
Simply quoting such fields does not help: spreadsheet applications
evaluate a leading <tt>=</tt>, <tt>+</tt>, <tt>-</tt>, or <tt>@</tt>
as a formula even inside a quoted CSV field.

The policy is applied to each \String field after write converters have
run and before CSV quoting, so neither option +force_quotes+ nor output
encodings can bypass the check. Non-\String values (including \Numeric
values such as \Integer and \Float) are never checked, so a real number
is never confused with a user-supplied \String that merely looks like
one.

A field is considered dangerous when, after skipping any leading
characters in CSV::SpreadsheetTextPolicy::SKIPPED_LEADING_CHARACTERS
(space, horizontal tab, line feed, vertical tab, form feed, and
carriage return), its first character is in
CSV::SpreadsheetTextPolicy::FORMULA_CHARACTERS
(<tt>=</tt>, <tt>+</tt>, <tt>-</tt>, <tt>@</tt>).
These checked character sets are a documented, conservative convention;
they do not claim to cover the formula syntax of every spreadsheet
application.

Default value (checking disabled):
  CSV::DEFAULT_OPTIONS.fetch(:spreadsheet_text_policy) # => nil

Accepted values:
- +nil+: no checking; output is exactly as without this option.
- <tt>:reject</tt>: raise CSV::SpreadsheetTextError for a dangerous
  field. The error carries the logical line number and the 0-based
  column number; the offending value is not included in the message
  by default.
- <tt>:prefix</tt>: prepend the default prefix <tt>"'"</tt> to a
  dangerous field, so the generated bytes show which fields were
  changed. A field that already starts with the prefix is left as-is.
- \Hash: keyword arguments for CSV::SpreadsheetTextPolicy.new:
  - <tt>action: :reject</tt> or <tt>action: :prefix</tt>.
  - <tt>prefix: string</tt>: custom non-empty prefix for
    <tt>action: :prefix</tt>.
  - <tt>expose_value: true</tt>: include the offending value in the
    CSV::SpreadsheetTextError message for <tt>action: :reject</tt>.

For examples in this section:
  ary = ['=SUM(A1:A2)', 'plain', -1, '-1']

Using the default, +nil+ (output unchanged):
  str = CSV.generate_line(ary)
  str # => "=SUM(A1:A2),plain,-1,-1\n"

Using <tt>:prefix</tt> (the \Numeric value +-1+ is left alone, the
\String <tt>'-1'</tt> is prefixed):
  str = CSV.generate_line(ary, spreadsheet_text_policy: :prefix)
  str # => "'=SUM(A1:A2),plain,-1,'-1\n"

Using <tt>:reject</tt>:
  CSV.generate_line(ary, spreadsheet_text_policy: :reject)
  # Raises CSV::SpreadsheetTextError
  # (Dangerous spreadsheet text in line 1, column 0.)
